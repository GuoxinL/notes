### 1. 单例模式基础

#### 1.1 概念

定义：确保一个类只有一个实例，并提供全局访问点

分类：设计模式 → 创建型模式

- 

核心代码：构造方法私有化（private），外部无法 new

#### 1.2 适用场景

|||
|---|---|
|全局配置|应用配置类|
|日志|Logger 单例|
|数据库连接池|Connection Pool|
|缓存|Cache Manager|
|线程池、文件管理器|-|


### 2. 五种实现方式

#### 2.1 懒汉式（线程不安全）

特征：用时再建，懒加载

```java
public class LHan {
    private static LHan instance; // 懒汉式

private LHan() {} // 私有构造方法

public static LHan getInstance() {
    if (instance == null) {
        instance = new LHan();
    }
    return instance;
}

}
```

|||
|---|---|
|延迟加载（lazy loading）|线程不安全（多线程下可能创建多个实例）|
|节省内存|不推荐生产使用|


#### 2.2 懒汉式（线程安全，加锁）

```java
public static synchronized LHan getInstance() {
    if (instance == null) {
        instance = new LHan();
    }
    return instance;
}
```

|||
|---|---|
|线程安全|每次 getInstance 都要加锁，性能差|
||锁粒度太大|


#### 2.3 饿汉式

特征：类初始化时就建好，类加载即实例化

```java
public class EHan {
    private static EHan instance = new EHan(); // 饿汉式

private EHan() {} // 私有化构造方法

public static EHan getInstance() {
    return instance;
}

}
```

|||
|---|---|
|线程安全（由 JVM 类加载机制保证）|浪费内存（用不到也创建）|
|实现简单|无 lazy loading 效果|


#### 2.4 双检锁（Double-Check Locking，DCL）

特征：综合懒汉式 + 饿汉式优缺点，最常用

```java
public class DoubleCheck {

private static DoubleCheck instance;

private DoubleCheck() {}

public static DoubleCheck getInstance() {
    if (instance == null) {
        synchronized (DoubleCheck.class) {
            if (instance == null) {
                instance = new DoubleCheck();
            }
        }
    }
    return instance;
}

}
```

关键细节：

|||
|---|---|
|外层 if|第一次判空，避免每次都进同步块（性能关键）|
|synchronized|保证线程安全|
|内层 if|防止多个线程同时通过外层 if 后重复创建|


注意：instance 字段应加 volatile 防止指令重排（JDK 1.5+ 才有正确语义）：

```java
private static volatile DoubleCheck instance;
```

|||
|---|---|
|线程安全 + 高性能 + 延迟加载|实现稍复杂；需理解 volatile|


#### 2.5 静态内部类（推荐）

```java
public class Singleton {

private static class SingletonHolder {
    private static final Singleton INSTANCE = new Singleton();
}

private Singleton() {}

public static final Singleton getInstance() {
    return SingletonHolder.INSTANCE;
}

}
```

核心原理：
- 外部类加载时，静态内部类不会被加载（lazy loading）
- 调用 getInstance() 才加载 SingletonHolder，此时才创建实例
- JVM 类加载机制保证线程安全（类初始化阶段加锁）

|||
|---|---|
|线程安全 + 延迟加载 + 实现简洁|只适用于静态域|
|比双检锁更优雅|实例域需要延迟初始化时不能用|


#### 2.6 枚举（最佳实践）

```java
public enum Singleton {
    INSTANCE;
    public void anyMethod() {
        // 业务方法
    }
}
```

|||
|---|---|
|实现最简洁|不能延迟加载（枚举实例在类加载时创建）|
|自动支持序列化机制|不适合需要传参构造的场景|
|绝对防止多次实例化（JVM 枚举机制）|-|
|线程安全（枚举实例天生单例）|-|


Effective Java 作者 Joshua Bloch 推荐的实现方式。最简洁 + 最安全。

### 3. 五种方式对比

|||||||
|---|---|---|---|---|---|
|懒汉（不安全）|❌|✅|最好|⭐|❌|
|懒汉（synchronized）|✅|✅|差|⭐|❌|
|饿汉式|✅|❌|好|⭐|❌|
|双检锁|✅|✅|好|⭐⭐⭐|❌（需 volatile）|
|静态内部类|✅|✅|好|⭐⭐|❌|
|枚举|✅|❌|最好|⭐|✅（JVM 保证）|


### 4. 场景选型决策树

- 你的应用是否需要延迟加载？
├─ 不需要（启动时即用）
│   ├─ 涉及反序列化？ → ✅ 枚举（最佳）
│   └─ 普通场景       → ✅ 饿汉式
│
└─ 需要延迟加载
   ├─ 实例域（不是静态域）→ ✅ 双检锁
   └─ 静态域            → ✅ 静态内部类
|||
|---|---|
|Spring Bean 单例|用容器（不需要自己实现）|
|工具类（无状态）|枚举 或 饿汉|
|重量级资源（DB 连接池）|双检锁 或 静态内部类|
|JDK / 框架内部单例|枚举（Joshua Bloch 推荐）|
|需要传参构造|双检锁（其他方式构造时无法传参）|


### 5. 常见坑 & 注意事项

#### 5.1 反序列化破坏单例

```java
// 双检锁 / 饿汉：序列化 → 反序列化会创建新实例
// 解决：添加 readResolve 方法
private Object readResolve() {
    return instance;
}
// 枚举天然免疫（JVM 内部实现）
```

#### 5.2 反射破坏单例

```java
// 反射调用 private 构造器可绕过单例
// 解决：在构造器中防反射
private Singleton() {
    if (instance != null) {
        throw new RuntimeException("禁止反射创建");
    }
}
// 枚举天然免疫（不能通过反射创建枚举）
```

#### 5.3 指令重排（DCL 必须 volatile）

```java
// 错误：DCL 没有 volatile 可能返回未初始化的对象
private static DoubleCheck instance;

public static DoubleCheck getInstance() {
    if (instance == null) {              // 1
        synchronized (DoubleCheck.class) {
            if (instance == null) {
                instance = new DoubleCheck();  // 2 这一步可能被重排
            }
        }
    }
    return instance;                    // 3
}
```

new 实际分 3 步：分配内存 → 初始化对象 → 赋值引用

指令重排可能导致：分配内存 → 赋值引用 → 初始化对象

此时其他线程看到 instance 非空，返回未初始化的对象 → NPE

- 


修复：private static volatile DoubleCheck instance;

#### 5.4 ClassLoader 破坏单例

不同 ClassLoader 可能加载出不同的 Singleton 类 → 多个实例

反序列化：自定义 readResolve 解决

最佳实践：枚举 一劳永逸

### 6. 知识延展

#### 6.1 Spring Bean 单例 vs 单例模式

||||
|---|---|---|
|范围|JVM 内一个类一个实例|容器内一个 Bean 一个实例|
|线程安全|自己保证|容器保证|
|实现|私有构造 + getInstance|@Component + @Scope("singleton")|


#### 6.2 相关模式

|||
|---|---|
|工厂方法|经常用单例实现工厂|
|建造者|内部 Builder 可以是单例|
|享元|多个"逻辑"对象共享，类似单例的扩展|
|模板方法|单例 + 模板方法 = 工具类|

### 附录 B：原文方法选用建议（保留原文）

懒汉式（包含线程安全和线程不安全两种方式）都比较少用
饿汉式和双检锁都可以使用，可根据具体情况自主选择
