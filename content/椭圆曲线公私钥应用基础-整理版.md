### 1. 椭圆曲线基础

#### 1.1 方程

y² = x³ + a·x + b  mod p

在有限域 Fp 上定义（p 为素数）

- 

曲线上的点 G 称为生成点（基点 Base Point）

#### 1.2 常见椭圆曲线（256-bit 主流）

||||||
|---|---|---|---|---|
|secp256r1（P-256 / prime256v1）|NIST / 国际|TLS、区块链|y² = x³ + ax + b|最广泛使用|
|SM2（sm2p256v1）|国密|国产合规场景|y² = x³ + ax + b|a, b 均非零|
|secp256k1（K1）|公链|比特币、以太坊|y² = x³ + 7|a=0, b=7（简化）|
|Ed25519|现代公链|Solana 等|twisted Edwards 曲线|高性能签名|


关键差异：K1 曲线 a=0, b=7（参数最简），P-256 / SM2 a,b 均非零。不同曲线的私钥不能互通。

### 2. 私钥

#### 2.1 本质

一个大整数（256-bit = 32 bytes）

- 

闭区间 [1, n-1]，n 是曲线阶（order）

#### 2.2 三种表示方法对比

||||||
|---|---|---|---|---|
|压缩表示|32 bytes / 64 hex|无|纯大端字节转 HEX|长安链 PK 模式（K1 曲线）|
|PKCS#8|可变|BEGIN PRIVATE KEY|DER 编码的 PrivateKeyInfo，嵌套 ECPrivateKey|长安链国密（最通用）|
|SEC1|可变|BEGIN EC PRIVATE KEY|DER 编码的 ECPrivateKey|长安链非国密（历史原因）|


#### 2.3 PKCS#8 内部结构（最常见）

```
PrivateKeyInfo ::= SEQUENCE {
    version                Version,            -- 0
    privateKeyAlgorithm    AlgorithmIdentifier, -- EC + SM2
    privateKey             OCTET STRING,        -- 嵌套 ECPrivateKey
    attributes         [0] IMPLICIT Attributes OPTIONAL
}

ECPrivateKey ::= SEQUENCE {
    version         INTEGER { ecPrivkeyVer1(1) } -- 1
    privateKey      OCTET STRING                  -- d（32 bytes 核心私钥）
    parameters  [0] OBJECT IDENTIFIER OPTIONAL   -- 曲线 OID（如 SM2）
    publicKey   [1] BIT STRING OPTIONAL           -- Q（68 bytes，含 04）
}
```

DER 编码注意：r/s 最高位是 1 时需加 0x00 前导，确保整数为正数。

### 3. 公钥

#### 3.1 本质

椭圆曲线上的坐标点 (x, y)，两个大整数

- 

由私钥 d 计算：Q = d·G（G 是基点）

#### 3.2 四种表示方法

|||||
|---|---|---|---|
|raw|64 bytes / 128 hex|`x||
|压缩|33 bytes / 66 hex|`0x02/0x03||
|未压缩|65 bytes / 130 hex|`0x04||
|X.509 / SPKI|可变|BEGIN PUBLIC KEY|SubjectPublicKeyInfo（最正式）|


压缩格式标识符：
- 0x02 → y 坐标是偶数
- 0x03 → y 坐标是奇数
- 由 x 解 y：y = √(x³ + ax + b) mod p

#### 3.3 X.509 SubjectPublicKeyInfo 结构

```
SubjectPublicKeyInfo ::= SEQUENCE {
    algorithm         AlgorithmIdentifier,
    subjectPublicKey  BIT STRING  -- 未压缩公钥
}

AlgorithmIdentifier:
    EC 公钥 OID:  1.2.840.10045.2.1
    SM2 曲线 OID: 1.2.156.10197.1.301 → SM2 / SM2P256V1
    未压缩标识:   0x04
    X 坐标:      32 bytes
    Y 坐标:      32 bytes
```

### 4. 签名

#### 4.1 签名流程（一般）

msg bytes → hash(msg) → 用私钥签 → 签名值 (r, s)

哈希算法：

||||
|---|---|---|
|SM2|SM3（国密强制）|哈希前要混入用户身份信息 ZA|
|其他（K1, P-256 等）|SHA-256|除非额外声明|


#### 4.2 SM2 签名特殊性

关键差异：不是对 msg 直接哈希，而是对 ZA || M 哈希

```
ZA = SM3(ENTL || UID || a || b || Gx || Gy || Px || Py)
    ↓
M' = SM3(ZA || M)  -- 用户身份摘要 + 消息
    ↓
用 M' 生成签名 (r, s)
```

ENTL = UID 的 bit 长度

UID：用户唯一标识（默认 16 字符 "1234567812345678"）

a, b：椭圆曲线参数

Gx, Gy：基点坐标

- 

Px, Py：用户公钥坐标

#### 4.3 签名实现注意

signWithOpts / verifyWithOpts：哈希在函数内完成（传 Opts 指定哈希算法）

sign / verify：需自己预先哈希好

- 

防止没哈希 / 二次哈希 的 bug

#### 4.4 签名值 (r, s) 表示

r：包含消息摘要的随机大整数（32 bytes）

s：包含私钥和 r 信息的大整数（32 bytes）
|||
|---|---|---|
|raw|64 bytes / 128 hex|`r|
|asn1|~69 bytes|SEQUENCE { r INTEGER, s INTEGER }（ECDSA-Signature）|

### 5. 地址

#### 5.1 为何不直接用公钥？

公钥较长（64-65 bytes），不便传输

公钥未经过校验，出错难发现

- 

通过哈希+校验和得到短地址 + 错误检测

#### 5.2 比特币地址算法（P2PKH）

- 




生成椭圆曲线公钥

- secp256k1 曲线
- 压缩（33 bytes）或未压缩（65 bytes）
公钥哈希
H₁ = SHA-256(pubkey)
H₂ = RIPEMD-160(H₁)        -- 20 字节公钥哈希

添加版本字节
比特币主网 P2PKH: 版本字节 = 0x00
20 字节 → 21 字节

校验和
checksum = SHA-256(SHA-256(前 21 字节))[:4]
21 字节 → 25 字节

Base58Check 编码
25 字节 → 25 个 Base58 字符 → 比特币地址
例: 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa

#### 5.3 以太坊地址算法（长安链主用）

- 




生成椭圆曲线公钥

- secp256k1 曲线
- 未压缩（64 bytes，去掉前缀 0x04）
Keccak-256 哈希
H = Keccak-256(pubkey)    -- 以太坊使用的 SHA3 变体

取后 20 字节
address = H[12:32]
例: 0x742d35Cc6634C0532925a3b844Bc454e4438f44e

- 




可选 EIP-55 校验

- 大小写混合校验
- 通过公钥哈希确定每个字母大小写
- 防止用户手动输入错误
### 6. 节点 nodeid（libp2p）

#### 6.1 概念

libp2p 中节点的唯一标识，由节点的公钥（TLS）推算

- 

格式：hash(tag || pubkey) → Base58

#### 6.2 为什么 K1 是 16U 开头，其他是 Qm 开头？

核心：开头几位为哈希算法 tag

|||||
|---|---|---|---|
|Ed25519|32 bytes 序列化 → SHA-256|mh.SHA2_256|~44 字符|
|secp256k1|33 字节压缩（短于 maxInlineKeyLength）→ 直接用公钥|mh.ID|~44 字符（16U 开头）|
|RSA 2048|序列化 → SHA-256|mh.SHA2_256|~44 字符|


Base58 长度参考：

||||||
|---|---|---|---|---|
|Ed25519|32|32|34|~44|
|secp256k1|33|32|34|~44|
|RSA 2048|294|32|34|~44|


Base58 长度 = 固定字符数，但解码后字节数 ≠ 固定（SHA-256 后通常是 34 字节）

### 7. x509 证书

#### 7.1 编码链路

ASN.1（结构描述） → DER（二进制编码） → PEM（Base64 + 头尾）

#### 7.2 关键字段：SKI（Subject Key Identifier）

证书公钥的哈希值（按指定哈希算法）

- 

用于证书链追溯

### 8. 密码机 / KMS

#### 8.1 核心目标

私钥不出机器（HSM）

使用 keyid 标识私钥/公钥

- 

通过标准接口访问

#### 8.2 接入方式

|||
|---|---|
|PKCS#11|国际标准密码机接口|
|SDF|国密标准密码机接口|


#### 8.3 调用流程

- 根据 label 找到 slot
- 针对该 slot，open session
- 用 password login session
- 用 session，keyid 访问对应密钥
- 组装 mech（密码学机制），传入密码机
- 获取签名/解密结果
#### 8.4 KMS（云密码机）

- 厂商接口各异（AWS KMS、腾讯云 KMS、Azure Key Vault 等）
- 通过 SDK 或 HTTPS API 调用

### 9. 加解密（拓展）

#### 9.1 非对称加解密

||||
|---|---|---|
|SM2|✅ 国密规定|支持非对称加解密；输出 C1C2C3 / C1C3C2 两种格式|
|国际椭圆曲线（P-256, K1）|❌ 默认只签名|需额外实现 ECIES 等算法|


SM2 密文组织方式（注意区别）：

||||
|---|---|---|
|C1 ‖ C2 ‖ C3|标准 GM/T 0003-2012 推荐|很多国密库默认|
|C1 ‖ C3 ‖ C2|早期 OpenSSL 国密改造、一些厂商 SDK|兼容旧实现|


工程中经常混淆"C1C3C2 格式"的密文需注意识别。

#### 9.2 对称加解密

||||
|---|---|---|
|AES|国际主流|128/192/256-bit 密钥|
|SM4|国密|128-bit 密钥，类 AES 结构|
