### 一、TCP 协议基础

#### 1.1 TCP 报文标志位（FLAGS 字段）

在 TCP 协议中，FLAGS 字段包含以下标识：

|||
|---|---|
|SYN|建立连接|
|FIN|关闭连接|
|ACK|响应/确认|
|PSH|有数据传输|
|RST|连接重置|
|URG|紧急指针|


#### 1.2 TCP 连接建立：三次握手

三次握手过程涉及 SYN 和 ACK 两个状态：

- 客户端发送 SYN 报文给服务端。
- 服务端收到 SYN 报文后，回应 SYN + ACK 报文。
- 客户端收到服务端的 SYN + ACK 报文后，回应一个 ACK 报文。
三次握手完成后，TCP 客户端和服务器端成功建立连接，可以开始传输数据。

配图说明（三次握手）：示意图左侧为客户端，右侧为服务器。服务器首先被动打开（bind）。随后出现三条带箭头的连线，依次为：

- 客户端 → 服务器：SYN
- 服务器 → 客户端：SYN-ACK
- 客户端 → 服务器：ACK
最终状态标注为“连接建立”。

#### 1.3 TCP 连接终止：四次挥手

四次挥手过程涉及 FIN 和 ACK 两个状态：

- 客户端首先调用 close，发送 FIN 报文，表示数据发送完毕（主动关闭）。
- 服务端接收到 FIN 报文，返回 ACK 报文。
- 服务端返回确认 FIN 报文（确认 close）。
- 客户端确认 FIN，返回 ACK 报文，连接中断。
由于每个方向都需要一个 FIN 和一个 ACK，因此通常需要 4 个报文。

配图说明（四次挥手）：示意图左侧为“客户”，右侧为“服务器”，标题为“TCP 连接终止需四个分节”。时序如下：

- 客户（主动关闭）→ 服务器（被动关闭）：FIN M
- 服务器 → 客户：ACK M+1（此时 read 返回 0）
- 服务器（close）→ 客户：FIN N
- 客户 → 服务器：ACK N+1
为什么终止需要四次分节？

TCP 的连接可靠性核心不是“不丢包”，而是“超时重传”。四次挥手保证了连接关闭存在延迟，防止连接关闭太快，导致重发的数据收不到确认。

#### 1.4 TCP 的可靠性

TCP 提供面向连接的、可靠的字节流服务。面向连接意味着两个使用 TCP 的应用（通常是一个客户和一个服务器）在彼此交换数据包之前必须先建立 TCP 连接。广播和多播不能用于 TCP。

TCP 通过下列方式提供可靠性：

- 应用数据被分割成 TCP 认为最适合发送的数据块（UDP 则保持数据长度不变）。TCP 传递给 IP 的信息单位称为报文段（segment）。
- 当 TCP 发出一个段后，启动定时器等待确认；若不能及时收到确认，将重发该报文段。收到数据后也会发送确认；延迟确认功能打开时由定时器触发确认时间点。
- TCP 保持首部和数据的检验和。如果收到段的检验和有差错，TCP 将丢弃该报文段且不确认，等待发端超时并重发。
- 由于 IP 数据报可能失序，TCP 报文段也可能失序；必要时 TCP 对收到的数据重新排序，以正确顺序交给应用层。
- 由于 IP 数据报可能重复，TCP 接收端必须丢弃重复数据。
- TCP 提供流量控制。连接每一方都有固定大小的缓冲空间，接收端只允许另一端发送缓冲区所能接纳的数据，防止较快主机使较慢主机缓冲区溢出。
### 二、TCP 与 UDP 的对比

#### 2.1 TCP 的优缺点

- 优点：可靠、稳定。体现在三次握手建立连接，以及数据传输过程中的确认、窗口、重传、拥塞控制机制；数据传完后还会断开连接以节约系统资源。
- 缺点：慢、效率低、占用系统资源高、易被攻击。建立连接需要时间；确认、重传、拥塞控制等机制会消耗大量时间；每个连接都会占用 CPU、内存等硬件资源；确认机制和三次握手机制也使其容易遭受 DOS、DDOS、CC 等攻击。
#### 2.2 UDP 的优缺点

- 优点：快、比 TCP 稍安全。UDP 没有握手、确认、窗口、重传、拥塞控制等机制，是无状态传输协议，传输速度快；没有 TCP 的这些机制，被攻击者利用的漏洞相对较少（但仍无法避免攻击，例如 UDP Flood）。
- 缺点：不可靠、不稳定。没有 TCP 的可靠机制，网络质量不好时容易丢包。
#### 2.3 核心区别

||||
|---|---|---|
|是否连接|面向连接|面向非连接|
|传输可靠性|可靠|不可靠|
|速度|慢|快|
|首部开销|20 字节|8 字节|


#### 2.4 应用场景

#### TCP 应用场景

效率要求相对低，但对准确性要求高的场景。例如：文件传输（准确性要求高、速度可相对慢）、接收邮件、远程登录。

典型使用 TCP 的应用：

- 浏览器：HTTP / HTTPS
- FlashFXP：FTP
- Outlook：POP、SMTP
- Putty：Telnet、SSH
- QQ 文件传输
#### UDP 应用场景

效率要求高，对准确性要求相对较低的场景。例如：QQ 聊天、在线视频、网络语音电话（即时通讯，速度要求高，偶尔断续可接受，且不可使用重发机制）、广播通信（广播、多播）。

典型使用 UDP 的应用：

- QQ 语音
- QQ 视频
- TFTP
### 三、小结

- TCP 适用于对可靠性、数据完整性要求高的应用。
- UDP 适用于对实时性、传输效率要求高的应用。
- 三次握手建立连接、四次挥手关闭连接是 TCP 面向连接特性的核心体现。
