### 一、简介

快速排序（Quicksort）使用分治法（Divide and conquer）策略把一个序列分为较小和较大的 2 个子序列，然后递归地排序两个子序列。



参考：分治法 — 维基百科

### 二、算法步骤

- 挑选基准值：从数列中挑出一个元素，称为「基准（pivot）」
- 分割（Partition）：重新排序数列，所有比基准值小的元素摆放在基准前面，所有比基准值大的元素摆放在基准后面（与基准值相等的数可以到任何一边）。分割结束时，基准的位置就已最终确定
- 递归排序子序列：递归地将小于基准值元素的子序列和大于基准值元素的子序列排序
终止条件：递归到最底部的判断条件是数列的大小是零或一，此时该数列显然已经有序。



⚠️ 基准值的选择对排序的时间性能有决定性影响。

### 三、基准值选择方法

|||||
|---|---|---|---|
|首/尾元素|固定选第一个或最后一个|实现最简单|已排序/逆序数列时退化为 O(n²)|
|随机选取|arr[rand()%n]|不依赖输入，最坏情况概率极低|随机数开销（可忽略）|
|三数取中（median-of-three）|取首/中/尾三个元素的中位数|显著降低最坏概率，工程首选|略复杂|




原文实现采用「中间元素」作为 pivot（arr[(start+end)/2]），对乱序输入较稳健，但对已排序输入仍可能退化。

### 四、配图（分治过程动画）

图内容描述（维基百科经典动画）：以柱状图表示数列，每次 partition 选定 pivot（高亮）→ 小值堆到左侧、大值堆到右侧 → 递归处理左右两个子区间 → 直至所有元素就位。动画中可以清楚看到「分」（左右分堆）与「合」（各子区间已自然有序）两个阶段。

### 五、复杂度分析

||||
|---|---|---|
|平均时间|O(n log n)|随机输入，划分基本均匀|
|最优时间|O(n log n)|每次划分都把数列等分|
|最坏时间|O(n²)|每次划分都极度不均（已排序 + 选首/尾为 pivot）|
|空间|O(log n)|递归栈深度（最坏 O(n)）|
|稳定性|不稳定|partition 交换可能改变相等元素相对顺序|
|适用规模|n 较大|常数因子小，缓存友好，实际最快|




与归并排序的对比：归并最坏也是 O(n log n) 但需要 O(n) 额外空间；快排原地但最坏退化。

### 六、Go 代码实现

原文采用双指针（i 从左、j 从右）+ 中间 pivot 的 Lomuto/Hoare 混合写法：

```go
func quickSort(arr []int, start, end int) {
    if start < end {
        i, j := start, end
        key := arr[(start+end)/2]          // 取中间元素为 pivot
        for i <= j {
            for arr[i] < key {
                i++                         // 左指针右移找 ≥ key
            }
            for arr[j] > key {
                j--                         // 右指针左移找 ≤ key
            }
            if i <= j {
                arr[i], arr[j] = arr[j], arr[i]
                i++
                j--
            }
        }
        if start < j {
            quickSort(arr, start, j)        // 递归排序左半
        }
        if end > i {
            quickSort(arr, i, end)          // 递归排序右半
        }
    }
}
```

### 七、常用优化

- 三数取中选 pivot：取 arr[start]、arr[mid]、arr[end] 的中位数作为 pivot，显著降低最坏概率
- 小数组切换插入排序：当子数组长度 < 16 时切换为插入排序（常数更小、缓存友好，Java/Go 标准库采用）
- 尾递归优化：对较长的一侧先递归，较短的一侧改为循环（避免栈溢出，Go 编译器会自动做）
- 3-way partition（Dijkstra）：当大量重复元素时，将等于 pivot 的元素一次性划出（Dutch National Flag），可从 O(n log n) 退化为 O(n) 排序
- 并行化：左右子数组独立，可多线程分治（但实践中受限于内存带宽，收益有限）
### 八、与其他 O(n log n) 排序对比

||||||
|---|---|---|---|---|
|快速排序|O(n²)|O(log n)|❌|平均最快，常数小，首选|
|归并排序|O(n log n)|O(n)|✅|链表/外部排序/要求稳定|
|堆排序|O(n log n)|O(1)|❌|最坏保证；常数大，较少独用|
|希尔排序|O(n^1.3)|O(1)|❌|简单实现，n 中等时可用|


选型建议：

- 默认选快排（尤其数组实现），因其缓存友好、平均最快
- 要求稳定 → 归并排序
- 内存极度受限（如嵌入式） → 堆排序
- n 极小或基本有序 → 插入排序
