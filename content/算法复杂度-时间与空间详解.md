### 一、为什么需要分析算法

对于一个给定的算法，通常要做两项分析：

- 正确性证明（数学层面）：用形式化证明、循环不变式、数学归纳法等方法证明算法正确
- 复杂度分析（性能层面）：在证明正确的基础上，分析算法的时间和空间代价
算法的时间复杂度反映程序执行时间随输入规模增长的量级，在很大程度上反映算法的优劣。

度量程序执行时间的方法：

||||
|---|---|---|
|事后统计|实际运行程序测时间|❌ 依赖硬件/软件环境、易掩盖算法本身优劣|
|事前分析估算|依据统计方法估算|✅ 仅依赖算法与输入规模，可比性好|


事前分析时，程序运行时间取决于：

- 算法采用的策略、方法
- 编译产生的代码质量
- 问题的输入规模
- 机器执行指令的速度


算法由「控制结构（顺序/分支/循环）」和「原操作（固有数据类型操作）」构成。为便于比较，通常选取一种基本原操作，以其重复执行次数作为算法时间量度。

### 二、时间复杂度

#### 2.1 时间频度 T(n)

一个算法中的语句执行次数称为「语句频度」或「时间频度」，记为 T(n)。

T(n) 与算法中语句的执行次数成正比。

#### 2.2 时间复杂度（大 O）

随着 n 不断变化，时间频度 T(n) 呈现一定规律。引入辅助函数 f(n)：



当 n → ∞ 时，若 T(n)/f(n) 的极限为不等于零的常数，则称 f(n) 是 T(n) 的同数量级函数。
记作 T(n) = O(f(n))，称 O(f(n)) 为算法的渐进时间复杂度，简称「时间复杂度」。

大 O 符号（Landau 符号）：

- 由德国数论学家 Paul Bachmann 于 1892 年《解析数论》首先引入，由 Edmund Landau 推广
- 含义：T(n) = O(f(n)) 表示存在常数 C，使 n → +∞ 时 T(n) ≤ C·f(n)，即 T(n) 的上界是 C·f(n)
- 只关心「主干」，抛弃细枝末节；f(n) 一般不加系数（如 O(2n² + n + 1) = O(3n² + n + 3) = O(n²)）
#### 2.3 常见时间复杂度阶

按数量级递增排列：

O(1)  <  O(log₂n)  <  O(n)  <  O(nlog₂n)  <  O(n²)  <  O(n³)  <  ...  <  O(nᵏ)  <  O(2ⁿ)  <  O(n!)

随问题规模 n 增大，复杂度增大，执行效率降低。应优先选多项式阶 O(nᵏ)，避免指数阶。

#### 2.4 增长曲线对比

图内容描述：横轴为问题规模 n（0~20），纵轴为 T(n)（0~2000），曲线对比 5 种复杂度：
- 500·log₂n：增长最缓（对数阶）
- 100n：线性增长
- 5n²：平方增长，n=20 时 T≈2000
- n³/3：立方增长，n=20 时 T≈2667
- 2ⁿ：指数级爆炸式增长，n≈11 即超过 2000

经验法则：c、log₂n、n、n·log₂n 为高效；2ⁿ、3ⁿ、n! 稍大 n 就会「卡死」。

#### 2.5 求解时间复杂度的步骤

- 找出基本语句：执行次数最多的语句，通常是最内层循环的循环体
- 计算数量级：只保留函数中的最高次幂，忽略低次幂和系数
- 用大 O 记号表示：将数量级放入大 O 记号中
例如并列两个循环：

```c
for (i=1; i<=n; i++)  x++;            // O(n)
for (i=1; i<=n; i++)
  for (j=1; j<=n; j++)  x++;          // O(n²)
```

总时间复杂度 = O(n) + O(n²) = O(n²)（取最大量级）。

#### 2.6 分析法则

||||
|---|---|---|
|顺序结构|求和法则|T₁(n) = O(f(n)), T₂(n) = O(g(n)) ⇒ T₁+T₂ = O(max(f(n), g(n)))|
|循环结构|乘法法则|T₁(n) = O(f(n)), T₂(n) = O(g(n)) ⇒ T₁·T₂ = O(f(n)·g(n))|
|选择结构（if）|—|主要耗时在 then/else 分支；条件判断 O(1)|
|复杂算法|分解|分成易估算的几部分，再用求和/乘法法则|
|常数系数|忽略|O(Cf(n)) = O(f(n))，C 为正常数|


#### 2.7 常见复杂度示例

#### O(1) — 常数阶

```c
Temp = i; i = j; j = temp;   // 三条语句频度均为 1
```

执行时间是常数，与 n 无关。即使有上千条语句，若不随 n 增长仍为 O(1)。

#### O(log₂n) — 对数阶

```c
i = 1;                        // ①
while (i <= n)  i = i * 2;    // ②
```

设 ② 的频度为 f(n)，则 2^f(n) ≤ n，即 f(n) ≤ log₂n，T(n) = O(log₂n)。

#### O(n) — 线性阶

```c
a = 0;  b = 1;                // ① 频度 = 2
for (i=1; i<=n; i++) {        // ② 频度 = n
    s = a + b;                // ③ 频度 = n-1
    b = a;                    // ④ 频度 = n-1
    a = s;                    // ⑤ 频度 = n-1
}
```

T(n) = 2 + n + 3(n-1) = 4n - 1 = O(n)

#### O(n²) — 平方阶

```c
sum = 0;                       // 1
for (i=1; i<=n; i++)           // n+1
  for (j=1; j<=n; j++)         // n²
    sum++;                     // n²
```

Θ(2n² + n + 1) → O(n²)（去低阶项 + 去常数项 + 去高阶项系数）

#### O(n³) — 立方阶

```c
for (i=0; i<n; i++)
  for (j=0; j<i; j++)
    for (k=0; k<j; k++)
      x = x + 2;
```

当 i = m, j = k 时最内层执行 k 次；i = m 时 j 可取 0..m-1，共 (m-1)m/2 次；i 从 0..n，总计 = n(n+1)(n-1)/6 = O(n³)。

#### 2.8 P vs NP

- P 问题（Polynomial）：多项式时间可解的算法 → O(nᵏ)，被认为是「有效算法」
- NP 问题（Non-deterministic Polynomial）：无法多项式时间求解，但可在多项式时间内验证一个解是否正确（如大数分解、Hamilton 回路）


例：判断 4294967297 是否为质数，直接求解需遍历至 √n；但若告知答案 641 × 6700417，可多项式时间内验证。

### 三、空间复杂度

#### 3.1 定义

空间复杂度 S(n) 是算法在运行过程中临时占用存储空间大小的量度，是问题规模 n 的函数。渐近空间复杂度常简称为「空间复杂度」。

#### 3.2 三个组成部分

|||
|---|---|
|① 算法本身占用的存储空间|与算法书写长短成正比（写短即可压缩）|
|② 输入/输出数据占用的存储空间|由问题决定，不随算法改变|
|③ 运行过程中临时占用的存储空间|随算法不同而异（这是我们关注的核心）|


就地算法（in-place）：临时工作单元数不随 n 增大而改变，如 O(1)，是节省存储的算法。

#### 3.3 常见空间复杂度

||||
|---|---|---|
|O(1)|常数额外空间|就地算法（如冒泡、堆排序）|
|O(log n)|与 n 的对数成正比|递归深度有限的分治算法|
|O(n)|线性空间|哈希表、桶排序、归并排序的辅助数组|
|O(n²)|平方空间|邻接矩阵存图等|


形参的影响：

- 形参为数组：只分配一个指针（机器字长）的空间
- 形参为引用：只分配一个地址空间，由系统自动引用实参
### 四、常用排序算法对比

表格整理（按平均时间排序）：

|||||||
|---|---|---|---|---|---|
|基数排序|O(log_R B)|O(log_R B)|稳定|O(n)|B 是真数（0-9），R 是基数（个/十/百）|
|冒泡排序|O(n³)|O(n²)|稳定|O(1)|n 较小时较好|
|插入排序|O(n³)|O(n²)|稳定|O(1)|大部分已排序时较好|
|希尔排序|O(n log n)|O(n^s)，1<s<2|不稳定|O(1)|s 是所选分组|
|快速排序|O(n log n)|O(n²)|不稳定|O(n log n)|n 较大时较好|
|归并排序|O(n log n)|O(n log n)|稳定|O(1)|n 较大时较好|
|堆排序|O(n log n)|O(n log n)|不稳定|O(1)|n 较大时较好|
|交换排序|O(n²)|O(n²)|不稳定|O(1)|n 较小时较好|
|选择排序|O(n²)|O(n²)|不稳定|O(1)|n 较小时较好|




注：上表中「冒泡」「插入」按某些教材的渐进分析可得平均 O(n²)，当按最差/特定度量才出现 O(n³)；不同教材的简化常数差异不影响大 O 量级结论。

选型经验：

- 小规模（n < 50）：插入排序往往最快（缓存友好、常数小）
- 大规模通用：快速排序（首选，平均最快），若要求稳定则归并排序
- 最坏情况敏感：堆排序（O(n log n) 最坏保证，无需额外空间）
- 部分有序：插入排序 / Timsort
- 数据范围有限：基数/计数排序可降至线性
### 五、关键结论速查

||||
|---|---|---|
|时间复杂度|O(1) / O(log n) / O(n) / O(n log n) / O(n²)|O(2ⁿ)、O(n!)|
|空间复杂度|O(1) / O(log n)（就地）|O(n²) 及以上（除非必要）|

- 任何程序员都应熟练掌握复杂度分析的概念和基本方法
- 善于从数学层面探寻其本质，才能准确理解其内涵
